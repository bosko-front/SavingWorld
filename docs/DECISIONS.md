## Phase 02 styling decisions 23 October 2026

Evidence: [PHASE_02](evidence/PHASE_02.md). Engineering choices made while executing Phase 02. D40 and D42 record owner UX instructions given at the end of the session, D41 the resulting library research and D43 the icon convention; neither changes v1.2 product scope.

| ID | State | Decision and reason | Tradeoff or consequence |
| --- | --- | --- | --- |
| D37 | Engineering baseline | Release 1.0 ships one light palette (the DESIGN_SYSTEM recommendation kept unchanged, plus pressed/disabled/subtle-border/feedback-surface roles) and forces the light appearance with `userInterfaceStyle: 'light'`, a cream root/splash background and a dark status bar. No theme context, no dark mode, no appearance toggle. | Native bars, sheets and keyboards stay legible over light surfaces when the OS is Dark. Changing to `automatic` later needs a full dark palette, contrast tests and device checks, plus a new native build (and a new app version once runtime 1.0.0 is shared). |
| D38 | Engineering baseline | Styling guardrails enforced by ESLint on `src/**`: no hex/rgb/hsl literals outside `src/shared/theme/palette.ts`, no raw palette/`PlatformColor`/`DynamicColorIOS` imports, no `allowFontScaling={false}`, `maxFontSizeMultiplier` or `Dimensions.get`. Contrast pairs are recalculated by a Jest test from the controls' own state color tables. The Expo config loader cannot import TS modules, so `app.config.ts` keeps one launch-color literal guarded by a test. | A legitimate exception needs an explicit lint disable with a reason. Palette edits fail fast in tests instead of drifting from the documentation. |
| D39 | Engineering baseline | The component gallery is development/test only: route `src/app/(tabs)/(home)/dev-gallery.tsx` inside `Stack.Protected guard={__DEV__}`, Settings shows its entry only in `__DEV__`, and the route requires `src/dev/component-gallery.tsx` only inside `if (__DEV__)`, which release bundles fold away. It lives in the Home stack (not the root stack) so native back labels and tabs behave like other detail screens. | A small route stub and the name `dev-gallery` remain in release bundles but are unreachable; release export checks confirm gallery code is absent. |
| D40 | Owner confirmed (23 October 2026) | Toasts may be used for feedback when they follow UX best practice: short committed-action confirmations only, one at a time, announced to VoiceOver, Reduce Motion aware, never for errors, destructive confirmation, essential data or celebrations. Rules in DESIGN_SYSTEM "Transient feedback". | Inline Notice and native alerts remain the error/confirmation path. Screens call a shared `showToast` wrapper, never a toast library directly. |
| D41 | Engineering baseline | UX library plan, each installed in its first-use phase with `npx expo install`: @expo/ui (already installed) for native date/currency/switch inputs; react-native-keyboard-controller only if Phase 03 needs it; sonner-native + react-native-svg + expo-symbols in Phase 06 (shared toast wrapper), expo-haptics in Phase 07; expo-image in 09; expo-notifications in 14; expo-iap in 15. Rejected: burnt (no release since March 2025), Lottie/Skia (D09), expo-blur/glass-effect, expo-font, expo-store-review, UI kits. | Each native addition needs a development rebuild and, once runtime 1.0.0 is shared, a new app version. sonner-native lacks its own VoiceOver announcement, so the wrapper adds it; swapping the engine later only touches the wrapper. |
| D42 | Owner requested, engineering baseline (23 October 2026) | Haptics through one shared helper with four semantic calls (success, warning, milestone, selection), each assigned to specific moments and phases in DESIGN_SYSTEM "Haptics"; at most one per user action, always paired with visible feedback, never for navigation, regression, purchases or decoration. No in-app toggle; iOS System Haptics setting applies. | `expo-haptics` arrives in Phase 07; phases 08, 10, 11, 13, 17 and 19 have explicit haptic tasks in their prompts. |
| D43 | Engineering baseline | Icons are SF Symbols only: NativeTabs `sf` for tabs, `expo-symbols` behind a shared `Icon` component with a semantic name map from Phase 06.

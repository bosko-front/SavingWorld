## Phase 05 persistence decisions 23 October 2026

Evidence: [PHASE_05](evidence/PHASE_05.md). Engineering choices made while executing Phase 05; no product rule changed.

| ID | State | Decision and reason | Tradeoff or consequence |

| D52 | Engineering baseline | One `AppDatabase` per file behind a small `SqlDriver` boundary (`src/data/db/`). A dedicated write connection runs every mutation as `BEGIN EXCLUSIVE … COMMIT` through one JavaScript promise queue (the serialized write path); a second, `query_only` read connection serves read snapshots, so uncommitted writes are never visible. Both enable `foreign_keys`; the writer sets WAL, `synchronous=FULL` and `busy_timeout=5000`. expo-sqlite's `withExclusiveTransactionAsync` is not used: in 58.0.13 it opens a new connection per transaction and begins the transaction before the task, so foreign keys could not be enabled on it. Migrations: ordered immutable list, history in `migrations` (version, name, FNV-1a 64 checksum, applied time); all pending migrations plus `foreign_key_check` run in one exclusive transaction; newer schema, changed history or a foreign database are refused unchanged.

## Known limitations and external dependencies

- Phase 09 limitations: layers load asynchronously, so a cold screen can show them a frame apart (Phase 10 owns reveals); memory figures are simulator-only (303 → 305-306 MB footprint from stage 0 to 10; the simulator draws on the Mac GPU); Duo fold/rotate with the scene not run natively (Jest relayout keeps the stage); Garden shows the scene fallback until Phase 17; `deps:check`/`doctor` 19/20 because of newer SDK 58 patches.
- Phase 08 limitations: the world region is a temporary box until Phase 09 art, and the callout shows percentages until the manifest supplies stage names; a date change while the app stays in the foreground shows at the next foreground or commit; "+ Add savings" covers a little content until scrolled (only the + above text scale 1.35); lifecycle actions are one tap further away in the ⋯ menu (D73); Duo closed/landscape and rotation were not re-shot (the stacked path is the same as the SE's).
- Phase 07.5 limitations (Add savings below the fold on the SE resolved in Phase 08, D70): closed-Duo screenshots in landscape only (Device Hub not scriptable); on the SE the stacked scene (≤ 45% height) pushes Add savings below the fold in the mocks, which Phase 08 must resolve with the real scene; next-milestone callout, scene and estimates are Phase 08/09.
- Phase 07 physical-device/Duo gate (D63): VoiceOver walkthrough of the entry form and History, felt haptics (Phase 19), and native rotation/fold of the entry form with a draft (Phase 21; Jest covers the window sequence and a native text-size relayout kept the draft), all in RELEASE_CHECKLIST. Phase 07 limitations: the Phase 06 deadline picker's duplicated inline label was fixed in Phase 07.5; History renders all rows without virtualization (Phase 21 profiles 10,000 entries); simulator taps/screenshots lag about one action, so screens were opened by deep link.
- Phase 06 physical-device gate (D60): the VoiceOver walkthrough (spoken toast announcements, focus order) cannot run in the iOS Simulator; it is checked in Phase 19 and Phase 21 on a physical iPhone (needs the owner's Apple Developer credentials and device registration). Phase 06 limitations: dates in our own text use the language tag while native pickers use the region (Phase 19); dev-client Metro warnings `onAnimatedValueUpdate with no listeners`; Finish UI is Phase 11; a completed goal must be reopened before archiving (D57).
- Phase 05 limitations: Hermes here has no `crypto.randomUUID`/`getRandomValues`, so ids use a `Math.random` UUID v4 (unique, not secret; D54). Opening sets WAL before the schema check, so a refused file may get its journal-mode flag changed (never schema or rows). Simulator-only SQLite evidence; physical-device file protection/low storage is Phase 21.
- Phase 04 carried check: `formatMoney`, `separatorsForLocale` and `today()` use `Intl`; Jest ran them on Node ICU only. Phase 06 observed their Hermes output on simulators (I01: exact digits, `today()` follows the device zone). The parser is strict by design (D50), so forms must explain each error code.
- Phase 03 release gates (not simulator passes): inner split view with the app on both sides and the full pose matrix on a physical iPhone Duo (D48; RELEASE_CHECKLIST, Phase 21). Device Hub can be automated through the macOS Accessibility API once Accessibility is granted to the Claude Code helper process (see ADAPTIVE_LAYOUT); the hinge slider does not respond to AX value changes, the pose buttons do.
- Known limitation: when the closed Duo in landscape collapses the native arrangement, AdaptiveGoalLayout switches to the stacked composition, which rebuilds both regions and drops keyboard focus (drafts and selection are kept).
- The iOS 27.1 simulator runtime supports only iPhone Duo; ordinary iPhones in this toolchain (iOS ≤ 27.0) always use the stacked fallback. Simulator tap automation is intermittent on the Duo; the lab's `?focus=draft` link avoids depending on taps.
- No physical-device development build yet; it needs the owner's Apple Developer credentials and device registration.
- App icon/splash image are Expo template placeholders until branding (Q09). Dev-client local-network and default ATS Info.plist entries need release privacy review (Phase 20/22).
- Phase 02 limitations (noncritical): pressed state and button keyboard-focus outline not observed on a simulator; VoiceOver not run; iOS 26 draws the back-button glass in its own color. iOS 26 transparent headers let scrolled content pass under the title by design; the native scroll inset keeps it reachable (Phase 03 inset policy). Shell screens still use temporary text.
